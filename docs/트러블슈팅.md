### TS-01 로컬 포트 충돌 (5432·8080·5173)
- **증상:** `curl localhost:8080/api/board`가 M-SPACE에 없는 응답(`UNAUTHORIZED`)을 돌려줌. `bootRun`을 띄우기도 전이었음.
- **원인:** 같은 PC에서 blog 프로젝트가 5432(PostgreSQL), 8080(API), 5173(Vite)을 이미 쓰고 있었음. 다른 서버의 응답을 M-SPACE 응답으로 착각할 뻔함.
- **해결:**
  - DB는 호스트 포트를 **5433**으로 바꿈 (`docker-compose.yml`, `application.yaml` 기본값 `DB_PORT:5433`).
  - API·화면은 기본 포트는 그대로 두고, 겹칠 때 `SERVER_PORT=8081 ./gradlew bootRun`, `API_TARGET=http://localhost:8081 npm run dev -- --port 5174`로 띄움 (`vite.config.js`에 `API_TARGET` 추가).
- **재발 방지:** 서버를 띄우기 전에 `lsof -nP -iTCP:8080 -sTCP:LISTEN`으로 포트 주인을 먼저 확인해요. README "로컬 실행"에 적음.

### TS-02 확인용 서버를 끌 때 다른 프로젝트 서버까지 끌 위험
- **증상:** 확인용으로 띄운 M-SPACE 서버를 `pkill -f "gradlew bootRun"`으로 끔. blog 서버도 같은 명령으로 떠 있었다면 함께 꺼졌을 것.
- **원인:** 프로세스 이름 패턴으로 끄면 다른 프로젝트 프로세스까지 걸림.
- **해결:** 이번에는 blog 서버가 다른 방식으로 떠 있어서 영향이 없었음 (8080 응답 200 확인).
- **재발 방지:** 내가 띄운 서버는 **포트로 PID를 찾아서** 꺼요: `kill $(lsof -t -iTCP:8081 -sTCP:LISTEN)`. 이름 패턴 `pkill`은 쓰지 않아요.

### TS-03 테스트 정리에서 `TRUNCATE ... CASCADE`가 운영 정책 행까지 지움
- **증상(예상):** `TRUNCATE users ... CASCADE`를 쓰면 `operation_policy`(updated_by가 users 참조)까지 비워져 다음 테스트에서 정책 행이 없음.
- **원인:** CASCADE는 참조하는 테이블 전체를 비워요. 또 `key_log`는 수정·삭제 금지 트리거가 있어 `DELETE`로는 못 지움.
- **해결:** `IntegrationTest.cleanUpDatabase()`에서
  1. 이력·예약 테이블은 `TRUNCATE`(행 트리거가 실행되지 않음)로 비우고,
  2. 정책 행은 V1 값으로 되돌리며 `updated_by = NULL`,
  3. `users`는 `DELETE` 후 identity를 재시작.
- **재발 방지:** 새 테이블을 추가하면 이 정리 SQL도 함께 고쳐요 (테이블이 빠지면 테스트끼리 데이터가 섞여요).

### TS-04 JDBC가 smallint를 Integer로 돌려줘 비교 실패
- **증상:** `expected: 540` / 실제 `540`인데 `containsEntry` 실패.
- **원인:** PostgreSQL JDBC는 `smallint`를 `Short`가 아니라 `Integer`로 돌려줌. 테스트에서 `(short) 540`과 비교함.
- **해결:** 테스트 기대값을 `int`로 바꿈.
- **재발 방지:** `queryForMap` 결과는 타입이 드라이버마다 달라요. 숫자는 `queryForObject(..., Integer.class)`처럼 타입을 지정해서 읽어요.

### TS-05 EXCLUDE 제약 위반에서 제약 이름 꺼내기
- **증상:** 예약 겹침(EXCLUDE 위반, SQLState `23P01`)을 `RESERVATION_TIME_CONFLICT`(409)로 바꾸려면 제약 이름이 필요한데, Hibernate가 EXCLUDE 위반의 이름을 알려주는지 확실하지 않음.
- **원인:** Hibernate의 PostgreSQL 제약 이름 추출은 UNIQUE·FK·CHECK 위주로 만들어져 있음.
- **해결:** `ConstraintNames.of()`가 Hibernate가 준 이름을 먼저 쓰고, 없으면 PostgreSQL 메시지의 `constraint "이름"`을 정규식으로 읽음. JdbcTemplate 경로는 `SchemaConstraintTest`로 확인함.
- **남은 일:** JPA(Hibernate) 저장 경로에서도 409로 바뀌는지 **3단계 예약 API 동시성 테스트로 확인**하고 이 항목을 갱신해요.
- **갱신(1단계):** JPA `saveAndFlush`로 학번 부분 유니크 인덱스를 위반시켜 `DUPLICATE_STUDENT_NO`로 바뀌는 것을 확인함 (`JpaConstraintMappingTest`). 동시 가입 5건 → 201 1건·409 4건 (`SignupApiTest`).

### TS-06 헤드리스 Chrome 375px 스크린샷에서 메뉴가 잘려 보임
- **증상:** `chrome --headless=new --window-size=375,700 --screenshot`으로 찍으니 상단 메뉴 오른쪽이 잘림.
- **원인:** 헤드리스 창에는 최소 폭이 있어서 실제 화면은 375px보다 넓게 그려지고 375px만 잘라서 저장됨. 레이아웃 문제가 아니었음.
- **해결:** CDP `Emulation.setDeviceMetricsOverride`로 화면 크기를 정확히 375px로 흉내 냄 (`e2e/cdp.mjs`의 `page.viewport()`). `scrollWidth <= clientWidth`와 메뉴 위치를 숫자로 검사함 (`e2e/check-layout.mjs`).
- **재발 방지:** 모바일 폭 확인은 스크린샷 눈대중이 아니라 e2e 점검의 숫자로 판단해요.

### TS-07 "md 파일을 고쳤다"는데 디스크에 변경이 없음
- **증상:** 사용자가 md 파일을 고쳤다고 했지만 M-SPACE의 md 5개 수정 시각이 모두 Claude의 마지막 편집 시각(16:29)과 같음. 홈 폴더·iCloud에서도 최근 수정된 md 없음.
- **원인(추정):** 에디터에서 저장하지 않았거나 다른 위치의 파일을 고침.
- **대응:** 문서를 덮어쓰기 전에 수정 시각을 확인하고, 변경이 없으면 사용자에게 저장 여부를 물어봄.
- **재발 방지:** 이제 git으로 관리하니 `git status`·`git diff`로 사용자 수정이 바로 보여요. 작업 시작 전에 `git status`부터 확인해요.

### TS-08 `gh` CLI 없이 GitHub 저장소·PR·릴리즈 만들기
- **증상:** `gh repo create` 실행 시 `command not found: gh`.
- **원인:** 이 PC에는 `gh`가 설치돼 있지 않음. git push는 키체인(osxkeychain)에 저장된 GitHub 인증으로 동작 중이었음.
- **해결:** `git credential fill`로 키체인 토큰을 읽어 GitHub REST API(`POST /user/repos`, `/branches/*/protection`, `/releases`, `/pulls`)를 직접 호출함. 토큰은 셸 변수로만 쓰고 출력하지 않음.
- **재발 방지:** CLAUDE.md 12장 "원격 저장소와 PR"에 방법을 적음. 편하게 쓰려면 `brew install gh` 후 `gh auth login`을 하면 돼요(새 도구 설치라 사용자가 정해요).

### TS-09 커밋 작성자 이름·이메일에 따옴표 문자(`“ ”`)가 들어감
- **증상:** `git log --format='%an <%ae>'` 결과가 `“happyzerojun” <“phr19656@naver.com”>`. 굽은 따옴표까지 이름·이메일 값에 들어 있음.
- **원인:** 전역 설정 `~/.gitconfig`에 따옴표째 저장됨(문서의 예시를 복사할 때 따옴표가 같이 들어간 것으로 추정).
- **영향:** 이메일이 GitHub 계정 이메일과 달라서 커밋이 `happyzerojun` 계정에 연결되지 않아요(잔디·기여자에 안 보임). 다른 프로젝트 커밋에도 똑같이 적용돼요.
- **해결(사용자 확인 후):** 전역 설정만 고치면 앞으로의 커밋은 정상이에요.
  ```bash
  git config --global user.name "happyzerojun"
  git config --global user.email "<GitHub에 등록된 이메일 또는 ID+happyzerojun@users.noreply.github.com>"
  ```
  이미 올라간 커밋은 이력 다시 쓰기 금지 규칙(12장)에 따라 고치지 않아요.

### TS-10 e2e가 다른 프로젝트 화면(5174)을 점검함
- **증상:** `check-layout`, `check-auth`가 첫 단계에서 `시간 초과`. 실패 스크린샷에 M-SPACE가 아니라 blog(OwnLog) 가입 화면이 찍힘.
- **원인:** 5173뿐 아니라 5174도 blog 개발 서버가 쓰고 있었음. `vite --strictPort`는 실패하고 끝났는데, 로그를 보지 않고 점검을 돌려 blog 화면을 열었음 (TS-01과 같은 종류).
- **해결:** 비어 있는 5175로 띄우고 다시 점검 → 33건 통과.
- **재발 방지:** `e2e/run-all.mjs`가 시작할 때 `BASE`의 `<title>`에 `M-SPACE`가 없으면 바로 멈춰요. 서버를 띄운 뒤에는 로그의 `Local:` 줄로 실제 포트를 확인해요.
