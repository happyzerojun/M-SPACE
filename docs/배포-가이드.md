# M-SPACE 배포 가이드

- 문서 버전: v0.1 (2026-10-21) · 대상: 서버를 맡는 사람(개발 학생, 정보전산원 담당자)
- 근거: `Dockerfile`, `deploy/`, `scripts/backup-db.sh`, `scripts/purge-personal-data.sql`, 요구사항 NF-11(배포)·NF-12(개인정보)

## 1. 한눈에 보기

```
학생 휴대폰 ──HTTPS(443)──▶ 리버스 프록시(Caddy 또는 학교 Nginx) ──▶ app(화면 + API, 8080) ──▶ db(PostgreSQL 17)
                              인증서 자동 발급·갱신, 보안 헤더          외부 포트 없음             외부 포트 없음
```

| 구성 | 내용 |
|---|---|
| app | 루트 `Dockerfile`로 만든 이미지 하나. React 화면(빌드 결과)과 Spring Boot API가 함께 들어 있어요 |
| db | PostgreSQL 17. 데이터는 도커 볼륨 `pgdata`에 남아요(컨테이너를 지워도 유지) |
| proxy | Caddy. `DOMAIN`으로 들어온 요청을 app으로 넘기고 HTTPS 인증서를 자동으로 받아요 |
| 백업 | `scripts/backup-db.sh` (cron, 매일 1회, 14일 보관) |

외부에 열리는 포트는 **80·443뿐**이에요. DB와 app 포트는 같은 도커 네트워크 안에서만 쓰여요.

## 2. 서버 준비

| 항목 | 최소 | 비고 |
|---|---|---|
| CPU·메모리 | 1 vCPU · 2GB | 방 5개, 하루 예약 수십 건 규모. JVM은 메모리의 75%까지 써요 |
| 디스크 | 20GB | DB·백업·이미지 |
| OS | Docker 24 이상이 도는 리눅스 | Ubuntu 22.04/24.04 권장 |
| 네트워크 | 80·443 인바운드 | 학교 방화벽에서 열어야 해요 |
| 도메인 | 서버 IP를 가리키는 DNS | 예: `mspace.<학과>.chosun.ac.kr` — 정보전산원 협의 사항 |

학교 서버에 이미 Nginx가 있으면 Caddy를 빼고 `deploy/nginx.conf.example`을 써요(4장).

## 3. 처음 배포하기

```bash
# 1) 소스 받기 (공개 저장소)
git clone https://github.com/happyzerojun/M-SPACE.git /srv/m-space
cd /srv/m-space && git checkout v0.4.0        # 배포할 릴리즈 태그

# 2) 비밀값 채우기 (deploy/.env는 커밋되지 않아요)
cp deploy/.env.prod.example deploy/.env
openssl rand -base64 48    # 이 값을 DB_PASSWORD, 한 번 더 만들어 JWT_SECRET에
vi deploy/.env             # DOMAIN, DB_PASSWORD, JWT_SECRET, BOOTSTRAP_ADMIN_* 채우기

# 3) 띄우기 (처음엔 이미지 빌드로 3~5분)
cd deploy && docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f app   # "Started BackendApplication"이 보이면 준비 완료
```

- 첫 실행 때 Flyway가 테이블·방 5개·운영 정책을 만들어요.
- `BOOTSTRAP_ADMIN_STUDENT_NO`·`BOOTSTRAP_ADMIN_PASSWORD`를 채워 두면 관리자가 한 명도 없을 때 관리자(조교) 계정을 하나 만들어요.
  그 계정은 **첫 로그인 뒤 비밀번호를 바꿔야** 다른 기능을 쓸 수 있어요.
- 관리자가 비밀번호를 바꾸면 `deploy/.env`에서 `BOOTSTRAP_ADMIN_*` 세 줄을 지우고 `docker compose -f docker-compose.prod.yml up -d`로 다시 띄워요.
- 관리자를 더 만들 때는 그 사람이 학생처럼 가입한 뒤, DB에서 역할을 바꿔요(관리자 지정 화면은 2차):
  ```bash
  docker compose -f docker-compose.prod.yml exec -T db psql -U mspace -d mspace \
    -c "UPDATE users SET role = 'ADMIN' WHERE student_no = '<학번>' AND status = 'ACTIVE'"
  ```

### 확인

```bash
curl -fsS https://$DOMAIN/api/policy        # 예약 규칙 JSON
curl -fsS https://$DOMAIN/ | grep -c root     # 화면 index.html
```
이 확인은 CI(`docker` 잡)도 PR마다 같은 방식으로 해요: 이미지 빌드 → PostgreSQL과 함께 실행 → 화면·API·401·초기 관리자 로그인.

## 4. 학교 Nginx 뒤에 붙일 때

1. `deploy/docker-compose.prod.yml`에서 `proxy` 서비스를 지우고, `app`에 `ports: ["127.0.0.1:8080:8080"]`을 넣어요(서버 안에서만 접근).
2. `deploy/nginx.conf.example`을 학교 Nginx 설정에 넣고 도메인·인증서 경로를 바꿔요.
3. `X-Forwarded-For`·`X-Forwarded-Proto`를 꼭 넘겨요. 앱이 실제 학생 IP로 로그인 요청 수를 세고(IP별 1분 20회), HTTPS로 인식해요.

## 5. 업데이트와 되돌리기

```bash
cd /srv/m-space && scripts/backup-db.sh          # 업데이트 전 백업
git fetch --tags && git checkout v0.5.0          # 새 릴리즈
cd deploy && APP_VERSION=0.5.0 docker compose -f docker-compose.prod.yml up -d --build
```

- DB 구조 변경은 Flyway가 시작할 때 자동으로 적용해요. 마이그레이션은 **추가만** 하고 고치지 않아요(CLAUDE.md 7장).
- 문제가 생기면 이전 태그로 `git checkout` 후 같은 명령으로 되돌려요. 새 버전이 DB 구조를 바꿨다면 업데이트 전 백업으로 복구해요(6장).
- 재시작 중 1분 안팎 접속이 끊길 수 있어요. 수업·시험 시간을 피해 학과와 정한 시간에 해요.

## 6. 백업·복구

```bash
# 매일 새벽 4시 15분 백업 (서버 crontab -e)
15 4 * * * cd /srv/m-space && scripts/backup-db.sh >> deploy/backups/backup.log 2>&1

# 복구 (서비스를 잠깐 멈추고)
cd /srv/m-space/deploy
docker compose -f docker-compose.prod.yml stop app
docker compose -f docker-compose.prod.yml exec -T db pg_restore -U mspace -d mspace --clean --if-exists < backups/mspace-YYYYMMDD-HHMM.dump
docker compose -f docker-compose.prod.yml start app
```

- 백업 파일에도 학번·이름·전화번호가 들어 있어요. `deploy/backups`는 권한 700, 파일은 600이고 14일 지나면 지워요. 서버 밖으로 옮길지는 학교 지침을 따라요.
- 시범운영 중 한 번은 복구 연습을 해 두는 걸 권해요(백업이 실제로 복구되는지 확인).

## 7. 개인정보 파기

| 언제 | 무엇을 | 방법 |
|---|---|---|
| 학생이 탈퇴를 요청할 때 | 관리자 화면 → 회원 → 비활성화(키 받기 전 예약은 자동 취소) → 파기 스크립트 1번 | `scripts/purge-personal-data.sql` |
| 시범운영 종료 후 30일 안 (학교로 넘기지 않을 때) | 회원·예약·키 기록·감사 기록 전체 | 같은 스크립트의 2번 블록 주석을 풀어서 실행, 이어서 `deploy/backups` 삭제 |

```bash
cd /srv/m-space && scripts/backup-db.sh   # 실수에 대비한 마지막 백업(파기 후 이 파일도 지워요)
docker compose -f deploy/docker-compose.prod.yml exec -T db psql -U mspace -d mspace -v ON_ERROR_STOP=1 < scripts/purge-personal-data.sql
```

## 8. 보안 점검표

| 항목 | 상태 | 근거 |
|---|---|---|
| 접속 구간 암호화 | HTTPS만 (80은 443으로 이동), HSTS 1년 | `deploy/Caddyfile` |
| 비밀번호 저장 | BCrypt 단방향 해시 | `SecurityConfig.passwordEncoder` |
| 로그인 무작위 대입 | IP별 1분 20회 넘으면 429, 없는 학번도 같은 시간이 걸리게 해시 비교 | `AuthRateLimitFilter`, `AuthService.login` |
| 권한 | 관리자 API는 `/api/admin/**` + ADMIN 역할, 남의 예약은 404 | `SecurityConfig`, 통합 테스트 |
| 개인정보 노출 | 현황판·에러·로그에 학번·이름·전화번호 없음, DB 에러 DETAIL 차단 | `BoardApiTest`, `DbErrorPrivacyTest`, TS-16 |
| 비밀값 | `deploy/.env`에만(커밋 금지), 컨테이너 환경 변수로 전달 | `.gitignore` |
| 포트 | 외부는 80·443만, DB·앱 포트 비공개 | `deploy/docker-compose.prod.yml` |
| 실행 계정 | 앱 컨테이너는 root가 아닌 사용자 | `Dockerfile` |
| 보안 헤더 | nosniff, X-Frame-Options DENY, Referrer-Policy | Caddy·Spring Security |
| 의존성 | Spring Boot 4.1.1, PostgreSQL 17, Node 22로 빌드 | `build.gradle`, `Dockerfile` |

정기 점검 권장: 월 1회 `git pull`로 보안 패치가 들어간 릴리즈 반영, 분기 1회 백업 복구 연습.

## 9. 로그와 장애 대응

```bash
docker compose -f docker-compose.prod.yml logs --since 1h app     # 앱 로그 (개인정보는 남기지 않아요)
docker compose -f docker-compose.prod.yml restart app              # 앱만 재시작
```

- 서비스가 멈추면 학과실은 **종이 대장으로 바로 돌아가요**(시범운영 기간 병행). 복구 뒤 종이에 적은 예약은 관리자가 따로 입력하지 않아도 돼요 — 그 시간대는 현장 운영으로 처리해요.
- 노쇼 처리는 1분마다 돌아서, 서버가 멈췄던 시간의 노쇼는 다시 켜진 뒤 한 번에 처리돼요. 장애 때문에 키를 못 받은 학생이 노쇼가 되면 관리자 화면 → 이용 제한에서 해제해요.
